# Contributing To ProofRoute

ProofRoute is trying to make model routing feel invisible during real coding work and undeniable when the proof appears in the terminal. Contributions are most valuable when they preserve that shape: the CLI should remain the primary interface, the transparent proxy should keep normal OpenAI-compatible clients boringly compatible, and every new proof surface should make latency, cost, policy, and privacy easier to verify without opening a hosted dashboard.

Before changing behavior, run the local proof loop that matches the risk of the change. `npm test` exercises the router, proxy, telemetry, classifier sidecar, smoke tests, and terminal rendering, while `npm run check` verifies JavaScript syntax across the executable surface and `npm run check:prose` enforces the paragraph-style documentation rule across the public repository surface. Changes to README, architecture notes, or other public project text should stay in paragraph form rather than bullets or numbered lists, because the repository is intentionally written like a coherent technical narrative instead of a settings catalog.

Routing changes should keep prompt content private by default. Telemetry may record intent, model, provider, policy, token counts, cost estimates, actual usage, savings, latency, status, cache state, streaming state, and fallback state, but it should not persist prompt text or completion text. Classifier and proxy integrations should also keep deterministic fallback paths in place so optional local acceleration never becomes a new availability or latency bottleneck.

The project is open to pragmatic additions that improve first-run trust, transparent proxy compatibility, local accelerator proof, and shareable terminal evidence. A good pull request usually makes one of those loops tighter, includes focused tests for the affected boundary, and leaves unrelated formatting churn out of the diff so reviewers can see the product decision clearly.

When a pull request changes the public face of the project, keep the README, package metadata, repository profile guidance, terminal proof assets, and GitHub pull request template in agreement. If a change claims local accelerator value, prefer prompt-free evidence from `proofroute classifier`, `proofroute classifier --bench`, or `doctor` with device profile metadata enabled so screenshots and JSON artifacts can show named hardware, warmup state, and lane behavior without exposing private prompts.
