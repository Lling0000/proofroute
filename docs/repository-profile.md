# Repository Profile

Use this page as the maintainer source of truth for the public repository surface. The GitHub About description should read `CLI-first OpenAI-compatible LLM router/proxy that routes prompts to the cheapest fast-enough model and proves speed, savings, and prompt-free privacy.` This description is short enough for GitHub, explicit enough for search, and honest about the product shape: transparent proxying, local intent routing, local and cloud model selection, prompt-free privacy, and terminal proof instead of a hosted dashboard.

The repository topics should be entered as `llm-router`, `llm-proxy`, `ai-gateway`, `llm-gateway`, `model-router`, `prompt-routing`, `model-selection`, `openai-compatible`, `transparent-proxy`, `ollama`, `vllm`, `local-llm`, `local-first`, `gpu-classifier`, `multi-gpu`, `onnxruntime`, `tensorrt`, `terminal-ui`, `cost-optimization`, and `vibe-coding`. These tags are deliberately balanced between discoverability and precision, so the project appears in searches for LLM routing, OpenAI-compatible proxying, local model workflows, CUDA and TensorRT-backed classification, and developer-tool economics without looking like keyword stuffing.

The npm package description should stay aligned with package metadata and say that ProofRoute is a CLI-first, zero-dependency OpenAI-compatible LLM router and proxy that routes each prompt to the cheapest fast-enough local or cloud model and proves speed, savings, and prompt-free privacy in the terminal. The npm keywords should mirror the GitHub topics where possible, put discovery terms such as `llm-router`, `ai-router`, `inference-router`, `openai-compatible`, `transparent-proxy`, `local-llm`, `coding-agent`, `cost-optimization`, `prompt-privacy`, and `vibe-coding` ahead of the extension story, and still retain broader registry terms such as `gpu-routing`, `multi-gpu`, `cuda`, `tensorrt`, `onnx`, and `onnxruntime`, because developers often discover routing infrastructure through registry search before they see the README hero. The package should also stay publish-ready through `npm run release:npm:dry-run`, which verifies the npm tarball surface without publishing and keeps the two CLI binaries, source tree, examples, docs, README, license, security posture, and environment template inside the package before a public registry launch.

The executable source of truth for the public repository face is `node ./bin/proofroute.js profile`, or `npm run profile` when a package manager is available. That command prints the GitHub About copy, topic line, npm description, npm keywords, README badge contract, social preview guidance, short launch pitch, Vibe Coding pitch, privacy proof command, launch readiness command, and routing proof commands as terminal-native output, while `node ./bin/proofroute.js profile --json` gives maintainers a machine-readable shape for release scripts. The no-credential public visibility gate is `node ./bin/proofroute.js profile --check-public` or `npm run profile:public:check`, which verifies that the README first-screen badges are still declared, the badge images can be fetched without credentials as an advisory signal, the GitHub owner, GitHub repository URL, and npm package registry entry are visible to ordinary users, the npm latest version matches the local package version, and the public metadata still matches the local profile. The external GitHub drift gate is `node ./bin/proofroute.js profile --check-github` or `npm run profile:github:check`, which reads the live repository About description, homepage, and topics through `GH_TOKEN`, `GITHUB_TOKEN`, or an authenticated `gh` session and fails when the public GitHub face no longer matches the local profile. The explicit remote mutation command is `node ./bin/proofroute.js profile --sync-github` or `npm run profile:github:sync`, which patches the About metadata and replaces the topic set with the profile values only when a maintainer deliberately asks for that sync. The release check is `node ./bin/proofroute.js launch`, `npm run launch`, `node ./bin/proofroute.js launch --core`, `npm run launch:core`, or `node ./bin/proofroute.js launch --json` when automation needs structured output, because it composes the repository face, zero-network routing proof, proxy smoke, privacy boundary, share assets, and classifier evidence status into one prompt-free readiness report before public copy becomes a claim; `node ./bin/proofroute.js launch --check-github` adds the live GitHub drift gate to that card for release moments where the external repository page itself must be proven current, `node ./bin/proofroute.js launch --check-public` adds the no-credential GitHub and npm visibility gate for public launch moments, and `node ./bin/proofroute.js launch --require-artifact-evidence --artifact-evidence classifier-linear-evidence.json --max-evidence-age-hours 24` with `npm run launch:artifact` marks the main accelerator claim as none while evaluating the local artifact proof separately. The core release proof archive is `node ./bin/proofroute.js release --core --out proofroute-release-pack` or `npm run release:core`, the ordinary-laptop artifact archive is `node ./bin/proofroute.js release --core --require-artifact-evidence --artifact-evidence classifier-linear-evidence.json --max-evidence-age-hours 24 --out proofroute-release-pack` or `npm run release:artifact`, the public preflight is `node ./bin/proofroute.js release --preflight --core --check-public`, the strict preflight is `node ./bin/proofroute.js release --preflight --require-evidence --evidence classifier-evidence.json --max-evidence-age-hours 24` or `npm run release:strict:preflight`, the local CI-safe archive command is `npm run release:pack:local`, the live GitHub maintainer archive is `node ./bin/proofroute.js release --out proofroute-release-pack --check-github` or `npm run release:pack`, and the hardware-claim version is `npm run release:strict`, because maintainers need a single prompt-free folder containing repository metadata, launch readiness JSON, `git-provenance.json`, copied SVG proof assets, dirty-worktree counts, public visibility status when requested, classifier evidence verification or an explicit no-accelerator-claim state, optional local artifact verification, freshness status, paragraph-only release prose, and `launch-copy.md` before a claim moves into a public post. The final publish gate is `node ./bin/proofroute.js publish --check-public --check-actions` or `npm run publish:preflight`, which checks package metadata, npm CLI executability, npm pack dry-run contents, npm publish dry-run metadata stability, npm registry identity, authenticated GitHub repository visibility, authenticated GitHub account search visibility, no-credential GitHub owner visibility, no-credential GitHub repository visibility, npm registry visibility, and recent GitHub Actions evidence before the repository tells ordinary developers to install from npm. The same publish report emits top-level `blockers` and `nextActions`, with stable blocker ids such as `npm_auth_missing`, `github_account_flagged_spammy`, `public_face_404`, and `github_actions_disabled`, so release automation and human maintainers can read the same evidence without reverse-engineering every nested check. When the account-level Actions layer itself needs to be tested, `node ./bin/proofroute.js publish --check-public --check-actions --probe-actions-dispatch` deliberately attempts a workflow dispatch and records the resulting blocker without pretending that repo-level Actions settings can repair user-level restrictions. When a platform blocker needs a human support trail, `node ./bin/proofroute.js publish --check-public --check-actions --probe-actions-dispatch --support-note` or `npm run publish:support-note` renders the same evidence as copyable, redacted, plain text while `--json` remains the priority for automation. The preflight path checks blockers without writing a release proof pack and skips proxy smoke by default so it can be used as a dry-run gate; maintainers can add `--smoke` when they want that extra execution check. This keeps repository tags, README badges, README language, package metadata, privacy posture, launch readiness, external GitHub metadata, public package visibility, npm publish readiness, source provenance, release proof packs, and launch copy from drifting apart as the product surface grows.

The social preview should use a capture derived from `docs/proofroute-terminal.svg`, `npm run share:svg`, or a fresh `proofroute share --svg` run. The image needs to foreground the terminal receipt, not an abstract logo, because the viral hook is the evidence: p95 routing latency, local-cloud split, classifier mix, model mix, speed lift, and exact dollar savings in a frame that looks like a real developer artifact. The profile command generates and checks the metadata and asset pointers that should be used, but GitHub social preview image upload remains a manual repository settings action because GitHub does not expose that image through the same About metadata and topics sync flow. Before a real ledger receipt becomes public launch material, `proofroute privacy --file .proofroute/events.jsonl` or `npm run privacy` should pass so the shareable proof is backed by an executable audit of the prompt-free boundary, and `proofroute launch --telemetry .proofroute/events.jsonl` or `npm run launch` should be the final local release card because it checks the repository face, zero-network value proof, proxy smoke, privacy result, SVG assets, and classifier evidence state together.
